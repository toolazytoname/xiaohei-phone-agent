# M6 public-Beta hardening acceptance — partial

Date: 2026-08-09  
Stress baseline: `0.2.0-alpha.1` (`versionCode=2`); current incremental candidate: `0.2.0-alpha.2` (`versionCode=3`)

## Proven gates

- Debug and release variants are distinct. `aapt2 dump badging` showed `application-debuggable` only on the debug APK. A release build using `androiddebugkey` was refused. A non-debuggable locally test-signed APK was produced only with the explicit `XIAOHEI_ALLOW_TEST_SIGNING=1` escape hatch and is not a public Release.
- Release builds require external keystore path, alias, store password, and key password. No key or password is stored in Git.
- The CycloneDX 1.5 SBOM generator emits the app component, APK hash when supplied, and the optional sherpa-onnx/model bundle hash and unresolved model-license notice.
- Configuration schema migration v1 maps legacy endpoint/model names, removes legacy keys, copies no token plaintext, and is idempotent. The installed app created `config_schema=1`.
- On the exact latest offline-ASR debug candidate, the real-device harness completed 100 deterministic actions: 100 success, zero dispatcher failure, zero fatal/ANR signature, and zero active recording client.
- Repository verification passed with 21 required artifacts, three valid JSON schemas, valid local links, no forbidden binary, no detected credential, and no private path/device identifier.
- Alpha.2 (`versionCode=3`) adds a bilingual threat model and an exact-APK static gate. The combined candidate passed signing, safe ZIP paths, credential signatures, permission allowlist, exported-component permission gates, and native-library inventory; SHA-256 was recorded. CycloneDX now covers the app plus pinned ASR and KWS bundles.
- Real-device migration passed: normal code 2→3 upgrade preserved config schema v1; normal 3→2 downgrade was rejected by Android; explicit maintenance downgrade preserved config; re-upgrade restored code 3 and retained the Assistant role.
- Transactional uninstall from code 3 stopped/verified DSP `DETACHED`, removed the app and Assistant role, and preserved the Companion. Fresh install restored code 3 and the Assistant role with Accessibility disabled.
- The reusable surface harness opened 14 Android Settings surfaces and 11 system apps on the physical phone: 25/25 expected package or documented system permission/Safety Center interstitials, zero launch failure, and zero Xiaohei Fatal/ANR. It did not auto-grant Contacts or Clock permissions.
- Fresh alpha.2 exposed and fixed a first-install camera permission issue caused by declaring CAMERA for torch support. Denial produced zero action and a recoverable state. With the stress harness temporarily granting and then restoring CAMERA, the exact alpha.2 candidate passed 100/100 actions, zero failures, zero Fatal/ANR, and zero recording residue.
- The on-device `diagnostics.v1` export produced versioned JSON with assistant/DSP/CPU state, capability and permission booleans, and config schema. It contained no serial, endpoint, token, notification text, UI tree, or private path and reported `public_log_safe=true`.
- Exact native versions and hashes were inventoried. Reproducible OSV queries returned zero known entries for inferred PyPI coordinates `onnxruntime@1.27.0` and `sherpa-onnx@1.13.4`; the documented coordinate limitation prevents treating this as a clean bill of health.
- Model-channel backup/restore now has a versioned, bounded text format with a pure-Java round-trip and malformed-input test. It includes ASR mode, Agent enabled preference, endpoint, and model only; no Token is serialised. A physical-device drill pasted a fixed backup, observed the visible result “Token cleared; Phone Agent remains disabled and no service started”, then restored the pre-test non-secret channel preferences and removed the private acceptance snapshot. The device had no configured Token before the drill; Token-bearing migration remains intentionally unsupported and requires re-entry.
- Build inputs are normalised before v2/v3 signing: generated DEX files receive a fixed ZIP timestamp, ZIP extra metadata is removed, and API-26-inapplicable v1 JAR signing is disabled. Two full combined-ASR/KWS debug builds with the same RSA key were byte-identical (`e4132ec99f7fc5846e2aa8977d69c27274c20e4f3474529df484ffdb87fff0dc`) and verified. `scripts/verify-reproducible-build.sh` repeats that gate for a selected build variant.
- A repository-external RSA-4096 Xiaohei release identity was created with its password held only in the local Keychain. The internal non-debug Alpha release candidate was built twice with that identity, byte-identical, and passed the exact scan: `6ad593561125af22fb10161f286c2f15a906af8734db9c065d3b80b2ffd9a26a`. Its certificate fingerprint and custody/rotation policy are documented without exposing private material.
- After USB was physically removed, Android 14 TLS Wireless debugging remained the only ADB transport. Over that unplugged connection, the exact alpha.2 debug build repeated the 100-action stress harness (100 success, zero failure, zero fatal/ANR, zero active recording client) and the 25-surface launch harness (25/25, zero Xiaohei fatal/ANR). This is a short interactive regression, not idle/power evidence.
- Alpha.3 freezes a publishable generic scope with no embedded model assets. The external RSA-4096 release identity produced the non-debug candidate twice byte-identically: SHA-256 `f4ce5eb9dcf6695a3f0cf63d4f9ae427c197170580c0bb894514d551a84c98b3`. The local release bundle records the clean source revision and binds it to the certificate fingerprint, one-component SBOM, checksums, and bilingual notes. The bundle has not been uploaded.
- The exact release-signed generic APK completed fresh install on the clean Android 14 ARM64 AOSP profile. Onboarding requested no permission; the base screen honestly reported no DSP profile and no bundled KWS model. Uninstall then left the package absent. This exact-release run supplements the broader M3–M5 debug acceptance and does not replace it.
- ClamAV 1.5.4 with 3,627,998 signatures independently scanned the exact generic release candidate and the exact private combined-model debug candidate (`5b5077f9fe12413ee268457a981c863057e546995c675d851343177dc6bc6e17`): two files scanned, zero infected. The result is bounded malware-engine evidence, not a vulnerability guarantee.
- An `age`/X25519 recovery archive was generated outside the repository, its identity stored in the local Keychain, and a full decrypt/hash drill matched the release keystore and certificate `1c0cf5bf518c3b63037dae70388974551bb1f0f851084328a48af13ebcc12c07`. It remains on the signing Mac as restricted **staging**; without separately controlled offline media, the offline-recovery gate is not yet closed.
- The full local-ASR/KWS debug alpha.3 candidate was upgraded over TLS Wireless ADB on the OnePlus 8T. It is `versionCode=4`, passed the exact static scan, left notification/Accessibility access disabled, and started no recording service. Its model weights remain private and outside Git/public Release assets.
- The v2 device-side idle monitor was independently exercised on the clean Android 14 ARM64 emulator with a zero-duration, screen-off run. Its completed raw TSV contained `requested_at`, `sampling_started_at`, and `preflight_wait_s`; collection passed with one non-interactive, unpowered, no-call, no-recorder, no-Xiaohei-wakelock sample. This validates the monitor's evidence format only, not physical OnePlus power.
- On 2026-08-11, the debug APK built from `33cdeea` (SHA-256 `e8a447b1ce459d6ec68d733507c74123b23dea25313c84fb690afe1cc6435167`) was upgraded in place on the OnePlus 8T; Assistant role and microphone permission remained present. The deterministic stress harness again completed 100/100 safe actions with zero dispatcher failure, Xiaohei fatal/ANR, or active recording client. On this Android 14/Lineage surface, sleeping/notification-shade state omitted `topResumedActivity`; the launch harness read `mFocusedApp` only as a read-only fallback and then passed all 14 Settings and 11 system-app targets (25/25) with zero Xiaohei fatal/ANR. This is short interactive evidence, not voice, privacy, idle-power, or mixed-workload acceptance.
- The same OnePlus 8T reported no configured or registered system TTS engine through package/default-engine read-only inspection. Xiaohei did not initialise speech, download an engine, or alter the TTS setting. System TTS qualification therefore remains a human owner setup and listening gate.

## Open M6 gates

The candidate is not a public Beta yet. Required evidence still missing: 8–24 hour unplugged idle/power, transfer of the verified encrypted signing recovery to separately controlled offline media, and final public-upload approval. The generic release scope embeds no models, so unresolved model redistribution rights no longer block that exact APK; they continue to block publication of the combined-ASR/KWS package. M5 now has its separate 10-app task matrix.
