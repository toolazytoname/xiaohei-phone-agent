# 新鲜、范围绑定的确认

[English](fresh-confirmation.md) · [未确认请求](unconfirmed-action-request.zh-CN.md) · [任务计划](rules-first-task-plan.zh-CN.md) · [状态](../STATUS.md)

状态日期：2026-08-10。`POLICY-002` 新增纯本地、内存中、一次性确认门。只有小黑位于前台、屏幕可交互且设备已解锁时，明确的本机用户手势才能生成短时确认；它不是模型回复、JSON 布尔值或可复用能力令牌。

## 绑定与生命周期

确认票据精确绑定：

- task ID、ActionRequest ID 与 Plan ID；
- 目标和完整展示内容；
- 调用方提供的单调时钟签发时间与过期时间；
- 本机用户手势来源和合格设备状态。

目标与内容只保存为使用唯一 confirmation ID 加盐的 SHA-256 摘要。票据只存在于一个进程对象中，永不持久化。状态只暴露是否活跃、剩余时间和结果，不含标识、目标、内容或摘要。

TTL 必须为 1–60 秒。授权最多成功一次，随后消费票据，而且授权本身不执行动作。精确到期、时钟回退、目标/内容/身份变化、非法范围、锁屏、屏幕不可交互、退后台、取消或任一比对失败都会销毁票据；再切回旧目标也不能恢复。

## 模型与权限边界

签发 API 接收有类型来源，`ASSISTANT_TEXT` 在构造票据前直接拒绝。因此 `confirmed=true` JSON、伪造工具结果或自然语言“已经同意”都不能确认。生产类不含模型客户端、文字解析器、Android 调用、工具网关、shell、网络、存储或日志路径。

`confirmation-grant.v1` 是内存票据的公开结构契约。它含加盐摘要但不含原始目标/内容，标记为不可公开日志，并强制 `source=local_user_gesture`、`single_use=true`、`persistence=memory_only`；它不是 `TOOL-002` 的能力令牌。

## 验收与剩余接入

纯 Java 矩阵包含 50 组/条：10 个精确一次放行、5 个目标变化、5 个内容变化、5 个 task/request/plan 变化、5 个过期/时钟失败、5 个设备状态失败、10 个助手伪造和 5 个缺失/取消/重放路径。全部结果零模型、零动作调用。4 个公开夹具独立接受一个新鲜票据，并拒绝助手来源、非法时窗和原始内容字段。

确认门仍有意不接 UI 或执行器。`TOOL-002` 现在会在纯 Java 授权矩阵中精确一次消费成功结果的内部 receipt，不暴露目标/内容，也不执行适配器。`UX-004` 仍须展示可访问的 App/目标/内容/权限/回滚预览并调用固定本机手势路径，这才能成为用户可见的生产流程。
