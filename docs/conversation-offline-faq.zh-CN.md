# 确定性离线 Conversation FAQ

[English](conversation-offline-faq.md) · [执行账本](execution-backlog.zh-CN.md) · [状态](../STATUS.md)

状态日期：2026-08-10。`CHAT-011` 在远端 Conversation 本轮未成功时提供刻意收窄的本地兜底。它是固定应用逻辑，不是生成式模型，也不能操作手机。

## 精确行为

1. Conversation 先走原有有界远端路径。
2. 取消永不触发兜底；其他远端/配置失败后，应用只用当前用户文字匹配 25 条中英文精确帮助短语。
3. 只支持五类：能力边界、是否离线、停止/取消、隐私/内存、是不是本地模型。
4. 命中后返回确定性答案，前缀固定为“本地固定 FAQ｜不是远端模型”，页面状态也明确写远端本轮未成功。
5. 未知、要求动作、组合问题、多行、注入或超长问题都没有本地答案，继续显示原来的远端/配置错误。

只归一大小写、句末标点和重复空格，不做语义相似或模糊匹配：“怎么停止？”会命中，“怎么停止是什么意思”不会命中。

## 权限与隐私

每个本地结果固定 `modelCalls=0`、`actionCalls=0`、`usesContext=false`。兜底类不导入 Android、网络、凭据、模型客户端、命令路由、工具网关、shell 或文件 API；不读上一轮，也不增加网络请求。如果此前远端路径已经尝试过请求，那次尝试仍然计数，兜底自身不增加调用。

命中的答案可以作为明确带标签的 assistant turn 留在现有有界、纯内存 Conversation 会话中，继续受锁屏、后台、结束、轮数、时间和 token 清理规则约束，不获得动作权限。

## 为什么不内置 0.6B 模型

长期架构只允许小型本地模型处理分类、固定 FAQ、隐私改写和断网解释。本任务选择固定 FAQ 路径，让公开 APK 不提交权重、不增大安装包、不引入模型许可证和常驻内存，也能获得可复现的离线帮助。未来本地模型适配器仍必须独立选择、明确标记、限制资源，并且不能规划或执行动作。

纯 Java 测试覆盖 25 条命中、10 条未知/动作/注入、超长输入、确定性输出和零权限；静态门禁证明它只接在远端失败之后，并确认 Conversation 未启用时在线程创建前返回。APK 通过构建和 v2/v3 签名验证。

在全新 Android 14 AOSP 模拟器上，从正常 onboarding/主页进入未配置远端渠道的 Conversation。输入 `what can you do` 后，页面显示远端失败状态和两种本地/非模型标签；动作型未知输入只得到“Conversation 渠道未启用”，前台仍是 `ConversationActivity`，没有打开其他 App，日志无 Fatal/ANR。没有使用 Mock 服务、网络模型、语音、截图或实体 OnePlus；APK、数据和 UI XML 随后均已清理。
