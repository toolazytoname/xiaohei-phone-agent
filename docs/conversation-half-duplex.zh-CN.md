# 有边界的半双工 Conversation

状态日期：2026-08-10。`CHAT-007` 把纯内存上下文边界接入用户可见的模型请求路径。它是零动作权限的文字对话功能，不是语音闭环，也不是 Phone Agent。

## 用户行为

公开主页进入一个中英双语的 **6 轮半双工**对话页面，固定预算为：

- 六个已完成的用户/助手 turn；
- 2048 个保守估算的正文 token；
- 从首条有效输入开始共五分钟；
- 同时最多一个模型请求。

模型回复期间，输入框和发送按钮禁用，取消按钮启用。失败或取消会回滚尚未配对的用户消息；下一次请求不会继承“幽灵 turn”。

页面显示已完成 turn 和估算 token 计数。可见文字只保存在 Activity 实例中，不写入 saved state、偏好、文件、数据库、日志、诊断或静态集合。

## 发给模型的上下文

客户端只接受奇数条、从用户开始并以用户结束的交替序列；最多 16 条，每条文字和总 token 都有上限。它在 `MemoryConversationSession` 的不可变快照前加上已有的“无工具”系统指令。

模型文字仍然只能显示。即使回复长得像 JSON、工具调用或操作指令，也不能到达 Android 动作、服务、广播、Phone Agent、OpenCode 或 root。

## 清空规则

出现以下任一情况，会取消请求并清空 Activity/会话自己持有的全部文字：

- 用户点击“结束聊天”，或输入精确匹配的中英文结束命令；
- 六轮、token 或五分钟预算结束；
- Conversation 的 endpoint/model/enabled profile 发生变化；
- 设备锁屏，或 Activity 离开前台；
- Activity 被销毁。

模型配置变化时页面会停在可见边界并要求用户再次发送，绝不把旧上下文静默交给新模型。结束命令采用精确匹配，句子里仅仅包含“结束”等词不会触发破坏性清空。

## 确定性覆盖

11 条纯 Java coordinator 用例证明：

- 指代追问会收到上一组用户/助手消息；
- 精确中英文结束命令不发网络请求；
- 总截止时间、切模型、锁屏和退到后台都会清空；
- 半双工 busy 状态拒绝第二条输入；
- 失败请求回滚后允许条件改变的重试；
- 三轮测试窗口在精确上限清空；
- 无效助手回复以独立原因关闭；
- 可公开状态没有 `String` 字段；
- 3–8 以外的追问轮数配置被拒绝。

仓库 UI 边界门禁还会确认七个稳定无障碍描述、公开主页标题、6 轮/5 分钟默认值、生命周期钩子、Activity 不导出以及零动作路径。

## AOSP 模拟器用户路径验收

2026-08-10，debug 候选包被全新安装到专用 Android 14 ARM64 模拟器，并通过正常 onboarding/模型渠道 UI 配置为宿主机 loopback 流式 mock；Phone Agent 保持关闭。

第一条输入为 `remember_xiaohei`，页面在 `1/6` 显示 `FIRST_CONTEXT_OK`。第二条输入为 `what_was_name`；Mock 只有在精确验证请求角色为 `system, user, assistant, user` 且包含上一组消息后，才返回 `REFERENCE_CONTEXT_OK`。页面显示两轮及 `2/6`。

点击“结束聊天”后，可见状态变成“聊天已结束，内存上下文已清空”；UI 树只剩空上下文提示，找不到先前正文。服务端两次检查均为 `context_ok=true`，Android 日志没有应用 fatal exception 或 ANR。验收没有截图，也没有调用真实模型。

随后已移除 reverse、测试 APK/数据和 mock 进程。本次没有访问实体 OnePlus 手机。
