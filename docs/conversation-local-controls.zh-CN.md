# 零调用本地 Conversation 控制

状态日期：2026-08-10。`CHAT-009` 为半双工页面增加明确的停止、重说、清空、继续和结束控制。它们都是本地状态转换，绝不会构造 Prompt Envelope 或模型请求。

## 控制语义

| 控制 | 本地效果 | 上下文效果 | 模型调用 |
|---|---|---|---:|
| 停止 | 如有在途请求只取消一次，并暂停输入 | 保留已完成 turn | 0 |
| 重说 | 重新显示上一条助手回复 | 不增加 turn | 0 |
| 清空 | 取消请求，清除页面/会话自己持有的文字，禁用输入 | 删除上下文 | 0 |
| 继续聊 | 离开暂停/已清空状态，恢复输入 | 保留暂停上下文，或从空会话开始 | 0 |
| 结束 | 像终止式清空一样取消并清除 | 删除上下文 | 0 |

清空或结束后，用户需要先点“继续聊”才能开始新会话。这样空状态与活跃状态是可见边界，不会把下一段文字静默提交。

当前文字产品中的“重说”只重新显示本地上一条回复。未来 TTS 适配器可以朗读同一份本地文字，但不得再次询问 Conversation 模型。

## 按钮与识别文字

停止、重说、清空、继续聊分别有独立按钮，结束保留为独立终止按钮。同一个精确匹配解析器接受 23 条中英文控制短语，因此未来 Conversation ASR 的 final 文本可以进入完全相同的本地路径。

匹配只在大小写和句末标点归一化后做精确判断。“停止”是控制；“停止是什么意思”仍是普通聊天。这样不会因为问题里提到一个控制词就破坏上下文。

本任务证明 ASR 文字兼容的控制解析，不证明真人声学识别。真实麦克风/ASR/TTS 仍受 `VOICE-*`、`CHAT-005` 和 `CHAT-012` 门禁约束。

## 幂等性

纯 Java 状态机记录 `ACTIVE`、`PAUSED` 或 `CLEARED`，以及请求和上一条回复是否存在。每个控制结果都有常量 `modelCalls=0`。

- 第二次停止不会重复取消。
- 第二次清空或结束不再改变状态，也不会恢复文字。
- 第二次继续聊不再改变状态。
- 重说可以再次请求，但不改变会话、不增加模型 turn。
- 暂停/已清空状态在继续聊之前拒绝发送。

9 组确定性用例覆盖 23 条精确短语、8 条非控制包含句、只取消一次、重说可用性、清空/结束遗忘、继续、暂停发送拒绝和五种零调用结果。
