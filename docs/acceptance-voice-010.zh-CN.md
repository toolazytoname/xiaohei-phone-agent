# VOICE-010 句子 TTS 队列验收

日期：2026-08-11

设备：OnePlus 8T（`KB2000`），Android 14

小黑：私有本地 ASR 调试构建，`0.2.0-alpha.3`（`versionCode=4`）；已安装 base APK SHA-256：`37f2c1f6f5f3c9d87637dda369a7e732e01ffbb4f8fda4359be8d03ca57fbf8d`

## 已实现边界

- 一条回复会被拆为带代际的有序句子队列：首句立即提交，下一句只能在当前 Android TTS utterance 完成后提交。
- 替换、停止、中断、超时和销毁都会使队列代际失效；迟到的引擎回调会被忽略，不会推进过期文本。
- 队列诊断只记录代际、序号、待播数量和回调延迟，不记录播报正文。
- 队列只在已选中的 Android 系统 TTS 适配器内工作；不启动服务端、网络请求、麦克风或常驻 CPU 唤醒词服务。

## 确定性校验

`SentenceTtsQueueTest` 覆盖首句立即可用、有序序号、替换失效、取消、迟到完成拒绝和零重叠。`TtsLifecycleTest` 覆盖中断以及只有用户点击“重说”才恢复，绝不自动续播。完整 Android 单测、静态队列门禁和私有签名 APK 构建均通过。

## OnePlus 真机证据

测试使用 UI 明确标识“不是远端模型”的本地固定 FAQ。由于 Conversation 页面只会在渠道启用后进入已有的失败回退，测试期间仅临时填入 `http://127.0.0.1` 和占位模型名；loopback 故意失败后进入固定 FAQ，不使用凭据，也不发出外网请求。测试后已恢复原状态：Conversation 关闭、地址/模型为空、本地 ASR、系统 TTS、CPU 唤醒词 OFF、DSP `ACTIVE(handle=4)`。

这些时间也说明验收措辞必须收敛：真实 AudioFlinger 输出发生在 TTS 引擎回调之后，自动化和本次测试均不能证明“人耳感知”小于等于 300 ms。

## 仍未关闭的边界

本项证明真机有序队列推进和排队内容取消；不证明真人可懂度、自然度、≤300 ms 可听打断、语音抢话/回声安全、蓝牙/耳机路由、长时间功耗或在线/中转 TTS 服务。这些仍属于 `VOICE-011`、`VOICE-012`、`CHAT-005/012` 及物理/真人门禁。
