# 厂商级智能手机助手交付计划

[English](product-delivery-plan.md) · [路线图](roadmap.zh-CN.md) · [架构](architecture.zh-CN.md) · [安全模型](../SECURITY.md)

本文把“能演示一次”与“可以交付、可以日常使用”分开。目标不是复制某一家厂商的私有服务，而是在 Android 公开能力、用户主动授权和少量已验证设备增强能力之上，交付一款体验接近厂商助手的小黑。

## 1. 产品目标与交付边界

### 1.1 首个真实产品目标

在当前 OnePlus 8T 上完成以下闭环：

> 息屏说“小布小布” → 听到提示音 → 说“打开相册” → 手机展示识别文字和动作 → 打开系统相册/图片选择器 → 小黑恢复待命。

首版继续使用已经实机验证的原厂词“小布小布”，先走通低功耗 DSP 到产品动作的完整链路；自定义“小黑小黑”必须作为后续独立资格项，不能以 CPU 常驻识别冒充 DSP 成果。

### 1.2 通用公开产品目标

普通 Android 用户即使没有 root、OnePlus 私有库或 Qualcomm DSP，也可以安装基础 APK，并通过 App 按钮、快捷设置、系统助手入口或按住说话使用核心能力。设备专属 DSP 只能作为独立增强包，缺失时不影响基础产品。

### 1.3 明确不做的事情

- 不伪造微信或其他 App 的私有协议，不承诺规避平台风控。
- 不让模型直接获得发送、删除、支付、安装或授权权限。
- 不在公开仓库或 Release 中分发 OEM APK、私有模型、厂商库、签名密钥、Token、私有 URL 或真实聊天记录。
- 不把进程存活、HTTP 200、按钮可点或单次成功当作端到端交付。
- 不为追求“全自动”隐藏麦克风、无障碍、通知读取或正在执行的任务。

## 2. 厂商助手对标功能清单

优先级定义：`P0` 是首个可用产品必须具备，`P1` 是公开 Alpha/Beta 需要具备，`P2` 是接近厂商级体验的增强项。

### 2.1 唤起与待命

- [ ] `P0` App 内按住说话，任何兼容设备都能使用。
- [ ] `P0` 快捷设置磁贴和桌面入口，显示当前可用状态。
- [ ] `P0` OnePlus 8T DSP Companion 支持 `status / arm / disarm / wake event`。
- [ ] `P0` DSP、语音会话、模型渠道和动作执行拥有独立状态，互不联动。
- [ ] `P0` 每次命中或失败后按有限状态机重新待命，不生成重复任务。
- [ ] `P0` 息屏、锁屏、解锁、切前后台和重启后的行为都有明确定义。
- [ ] `P1` 可选 Android 默认助手入口与长按电源键/系统手势入口。
- [ ] `P1` 可选 CPU 关键词模式，带持续前台通知和明确功耗提示。
- [ ] `P1` 唤醒灵敏度、误唤醒抑制、冷却时间和声音反馈可配置。
- [ ] `P2` 自定义“小黑小黑”关键词通过准确率、功耗和回滚资格。
- [ ] `P2` 耳机、蓝牙、车载与外接麦克风场景。
- [ ] `P2` 多人环境中的可选声纹偏好；不得作为支付或安全认证。

### 2.2 听取、识别与播报

- [ ] `P0` 唤醒后才开启短时命令音频，待机阶段不上传原始音频。
- [ ] `P0` VAD/端点检测能判断用户说完，支持超时和取消。
- [ ] `P0` 中文流式 ASR，边识别边显示文字，并给出可理解的失败原因。
- [ ] `P0` 本地提示音或短 TTS 反馈“已唤醒、正在执行、完成/失败”。
- [ ] `P0` 音频会话结束后立即释放麦克风并恢复待命。
- [ ] `P1` ASR 本地/中转站渠道切换，与 Phone Agent 模型渠道独立。
- [ ] `P1` 常用 App 名称、联系人别名和本机术语纠错词典。
- [ ] `P1` 说话中断、播报打断和一次追问。
- [ ] `P2` 连续对话、多轮指代和上下文过期机制。
- [ ] `P2` 离线短命令 ASR/意图识别兜底。

### 2.3 意图理解与任务规划

- [ ] `P0` 确定性命令优先，不为“打开相册”等固定动作调用大模型。
- [ ] `P0` 语音文本先解析为版本化 `Intent`，不能直接变成点击坐标。
- [ ] `P0` 未注册工具、参数缺失、目标歧义时拒绝猜测并向用户确认。
- [ ] `P0` 每个任务有唯一 ID、最大步骤、总超时和取消标志。
- [ ] `P0` 模型输出必须经过 Schema 校验和策略引擎。
- [ ] `P1` 简单路由可使用手机本地小模型；复杂规划可走用户中转站。
- [ ] `P1` 任务分解、逐步验证、一次有证据的恢复尝试。
- [ ] `P1` 当前屏幕、最近一次任务和用户明确授权的上下文注入。
- [ ] `P2` 个人偏好与长期记忆，默认本地、可查看、可删除、可关闭。
- [ ] `P2` 成功轨迹编译为可复用 Skill，失败轨迹转成回归用例。

### 2.4 手机动作能力

- [ ] `P0` 公开 Intent：打开 App、相册、浏览器、设置页、拨号盘和地图目标。
- [ ] `P0` 基础系统控制：音量、亮度、手电筒、Wi-Fi/蓝牙设置入口；受系统限制的动作明确提示用户接管。
- [ ] `P0` 所有动作返回 `success / partial / needs_user / failed / cancelled`。
- [ ] `P0` 动作前检查目标 App、锁屏状态、权限和重复请求。
- [ ] `P0` 低风险动作也必须可见、可取消、可追溯。
- [ ] `P1` 通知访问：汇总通知来源、数量和公开字段，不遍历聊天数据库。
- [ ] `P1` 无障碍执行：语义节点优先，坐标点击只作受控回退。
- [ ] `P1` 截图只在语义树不足时按需采集，任务结束即释放；敏感 App 默认禁用。
- [ ] `P1` 文本输入、滚动、返回、选择和可逆设置的适配器。
- [ ] `P1` 10–15 个常用 App 的版本化任务适配和失败说明。
- [ ] `P1` 消息回复只生成草稿、展示联系人和内容，并要求当次确认。
- [ ] `P2` 跨 App 多步任务和状态恢复。
- [ ] `P2` 日历、提醒、导航、媒体和智能家居的公开集成。
- [ ] `P2` 视觉定位与语义树融合；每一步执行后重新观察，不盲目连点。

### 2.5 用户界面与交互

- [ ] `P0` 首次启动向导解释麦克风、通知、无障碍和设备增强包的用途。
- [ ] `P0` 首页展示唤醒后端、ASR、Phone Agent 模型、动作服务四类独立状态。
- [ ] `P0` 状态机可见：`OFF / ARMED / LISTENING / THINKING / CONFIRMING / ACTING / ERROR`。
- [ ] `P0` 一张任务卡展示“听到了什么、准备做什么、正在做哪一步、结果是什么”。
- [ ] `P0` 全局停止按钮在 App、前台通知和任务浮层上都可触达。
- [ ] `P0` 错误信息包含原因、当前影响和一个有效解决入口。
- [ ] `P1` 快捷设置磁贴、桌面微件、系统助手会话 UI 和可选浮动按钮。
- [ ] `P1` 历史记录默认脱敏，可逐条删除、一键清空、关闭保存。
- [ ] `P1` 模型配置页显示渠道名、模型名、连通性和成本/本地属性，不显示 Token。
- [ ] `P1` 权限中心展示“已授权、使用原因、最近使用、撤销入口”。
- [ ] `P2` 锁屏、耳机和车载场景的紧凑反馈。
- [ ] `P2` 无障碍、字号、深色模式和中英文完整适配。

### 2.6 模型与渠道路由

- [ ] `P0` Phone Agent 使用独立配置，不与 Claude Code、OpenCode、Happy 的 active profile 联动。
- [ ] `P0` 可复用同一中转站 URL/Token 来源，但写入独立、可回滚的渠道配置。
- [ ] `P0` Token 存 Android Keystore/加密存储，日志和 UI 永不回显完整值。
- [ ] `P0` 切模型只切配置，不隐式启停 llama.cpp、Happy 或 OpenCode Web。
- [ ] `P0` 每个渠道有低成本健康检查，不用完整 Agent 任务测试连通性。
- [ ] `P1` 本地小模型承担路由、离线固定命令和简单摘要。
- [ ] `P1` 复杂屏幕理解和规划使用用户选择的远端模型。
- [ ] `P1` 超时、限流、余额不足、上下文过长和格式错误有明确状态。
- [ ] `P1` 失败回退最多一次，不能在多个付费模型之间无限重试。
- [ ] `P2` 根据隐私、网络、时延和成本自动推荐渠道，但最终选择始终可见。

### 2.7 安全、隐私与平台边界

- [ ] `P0` 动作风险分为低、中、高和默认禁止四级。
- [ ] `P0` 发送、删除、购买、安装、授权和安全设置必须绑定目标/内容进行新鲜确认。
- [ ] `P0` 锁屏时只允许白名单低风险动作；隐私内容默认不播报。
- [ ] `P0` 支付、银行、密码管理器、验证码和 DRM 页面默认不观察、不截图、不自动化。
- [ ] `P0` 麦克风、通知和无障碍使用必须符合 Android 可见性要求。
- [ ] `P0` 日志默认脱敏，不保存原始音频、完整聊天正文或凭据。
- [ ] `P0` 每个高权限组件最小职责、独立 UID、无网络或无动作权限（按职责二选一）。
- [ ] `P0` 紧急停止、超时、重复动作保护和卸载/回滚路径。
- [ ] `P1` 每 App allowlist/denylist 与能力开关。
- [ ] `P1` 微信等平台默认只做通知汇总、打开官方 App 和确认前草稿；不承诺账号零风险。
- [ ] `P1` 诊断包导出前二次脱敏和用户预览。
- [ ] `P2` 威胁模型、依赖扫描、SBOM、签名和漏洞报告流程。

### 2.8 Android 系统工程与稳定性

- [ ] `P0` 前台服务、音频焦点、来电、闹钟、媒体播放和蓝牙切换生命周期正确。
- [ ] `P0` 进程被杀、服务崩溃、网络切换、模型超时后能够回到可解释状态。
- [ ] `P0` 开机不自动获得不必要权限；只有用户开启的模式才恢复。
- [ ] `P0` 升级、降级、清数据和卸载不会留下 DSP 模型、麦克风会话或持久 wakelock。
- [ ] `P0` DSP Companion 使用唯一 UID，只负责 SoundTrigger 生命周期和脱敏事件。
- [ ] `P1` Android 默认助手角色和 `VoiceInteractionService` 能力探测。
- [ ] `P1` Doze、后台限制、电池优化和 OEM 保活提示。
- [ ] `P1` App/系统升级后的迁移与兼容检查。
- [ ] `P2` 多用户、工作资料、外屏/折叠屏和更多 ROM 适配。

### 2.9 可观测性、测试与支持

- [ ] `P0` 本地结构化事件：状态变化、动作结果、耗时和脱敏失败指纹。
- [ ] `P0` 同一失败指纹没有新证据时不重复声学测试、截图或模型调用。
- [ ] `P0` 单元测试覆盖状态机、Schema、风险策略和动作幂等。
- [ ] `P0` 真机自动化覆盖安装、权限、启停、唤醒、执行、取消、重启和卸载。
- [ ] `P0` 固定低风险任务集至少连续通过三轮。
- [ ] `P0` OnePlus 8T DSP 三次冷启动、三次启停和三次声学命中。
- [ ] `P0` DSP OFF/ARMED 物理拔线功耗 A/B，检查 AudioRecord 和 AP wakelock。
- [ ] `P1` 噪声、远场、口音、误唤醒、拒识、蓝牙和边说边播测试。
- [ ] `P1` 20+ App/页面版本矩阵和每周回归。
- [ ] `P1` 8–24 小时待机、100 次短任务、弱网/断网和异常恢复压力测试。
- [ ] `P1` 所有发布结论带设备、版本、步骤、期望、实际、证据和回滚记录。
- [ ] `P2` 经用户同意的匿名崩溃统计；不采集语音或任务正文。

## 3. 分阶段交付顺序

### M0 — 基线冻结与产品契约（当前）

**已有证据**

- OnePlus 8T 上原厂“小布小布”已完成息屏声学输入 → Qualcomm ADSP/LPI → 二阶段 RNN → Android callback。
- 通用 Android 开发版已完成手动事件 → 公开 Intent → 系统图片选择器。
- 已有 Wakeword、Action Request、风险模型和 OnePlus DSP Companion 的公开边界。

**退出门禁**

- [ ] 修正所有 README 状态，使“开发 APK”和“公开 Release”不混淆。
- [ ] 冻结 `wakeword-event.v1`、`action-request.v1`、助手状态机和错误码。
- [ ] 建立真机验收模板、失败指纹和不重复重试规则。

### M1 — OnePlus 8T 可用纵切

**目标**：先交付一条每天都能复测的语音闭环。

- [ ] 完成最小 DSP Companion 或受控本机兼容适配器。
- [ ] 主 App 增加 DSP 状态、开启、关闭和最近命中时间。
- [ ] 唤醒命中后启动 3–10 秒短音频会话。
- [ ] 接入一个中文 ASR 渠道并显示实时/最终文字。
- [ ] 固定意图“打开相册”，无 LLM 调用。
- [ ] 完成提示音、动作结果、失败恢复和自动重新待命。
- [ ] 三次冷启动、三次启停、三次息屏声学闭环均通过。
- [ ] 卸载和回滚后没有残留模型、录音、wakelock 或高权限包。

**交付物**：本机签名 APK、设备增强包、安装/回滚脚本、OnePlus 8T 操作卡和一份脱敏验收记录。

### M2 — 日常可用的短命令助手

**目标**：不靠演示路径，覆盖常用低风险需求。

- [ ] 10 个确定性命令：打开 App/设置/相册/网页、手电筒、音量、拨号盘、导航目标等。
- [ ] 独立的 ASR 与 Phone Agent 模型配置页。
- [ ] App 按住说话、快捷设置磁贴、前台通知和全局停止。
- [ ] 一次追问、歧义确认、超时、取消和网络失败处理。
- [ ] 连续 30 条固定命令成功，无重复动作。
- [ ] 重启、息屏、来电和网络切换后恢复正确。

**交付物**：可日常使用的内部 Beta、真机任务清单、已知限制和诊断导出。

### M3 — 通用 Android Alpha

**目标**：把产品从这台 OnePlus 8T 中抽离出来。

- [ ] 无 root 的基础 APK，可通过按住说话、磁贴或助手入口使用。
- [ ] 运行时兼容性探测；不支持 DSP 的设备明确显示基础模式。
- [ ] CPU 唤醒词作为显式可选项，先通过功耗测量再提供。
- [ ] OnePlus DSP 从主 APK 分离为设备 profile 工件。
- [ ] 至少一台非 OnePlus 设备完成安装和核心动作回归。
- [ ] 新设备首次安装、拒绝权限和离线场景都不会陷入死循环。

**交付物**：双语公开 Alpha APK、校验和、安装指南、权限说明、兼容矩阵和 Release Notes。

### M4 — 通知与确认式消息助手

**目标**：提供有价值的个人助手能力，同时守住账号和隐私边界。

- [x] 用户主动授权通知访问，按 App 汇总未读通知。
- [x] “有没有未读消息”仅依据系统通知字段并说明局限。
- [x] “帮我回复”生成草稿，展示 App、联系人和完整待发内容。
- [x] 每次发送前进行绑定目标/内容的确认；默认允许用户亲自点击发送。
- [x] 锁屏、隐私通知、撤回和通知已消失场景处理。
- [x] 微信真实主账号不做无人值守、批量或隐蔽自动发送。

**交付物**：通知隐私说明、消息动作风险测试，以及独立 AOSP Messaging 合成身份的隔离验收记录（见 [M4 验收](acceptance-m4.zh-CN.md)）。

### M5 — 可见的 Phone Agent

**目标**：执行跨 App 多步任务，但全程可观察、可打断。

- [ ] Accessibility 语义树观察、版本化快照和 per-app 限制。
- [ ] 截图视觉回退只在语义不足时触发。
- [ ] 工具调用和每步结果 Schema；执行后重新观察。
- [ ] 最大步骤、总时限、一次恢复、重复点击保护和全局停止。
- [ ] 10–15 个常用 App 的低/中风险任务回归。
- [ ] 支付、银行、凭据和验证码页面默认拒绝自动化。

**交付物**：动作适配器 SDK、App 兼容矩阵、成功轨迹 Skill 和失败回归库。

### M6 — 公开 Beta 与可靠性工程

- [ ] 8–24 小时待机和功耗门禁。
- [ ] 100 次短任务稳定性与异常恢复。
- [ ] 20+ App/页面版本持续回归。
- [ ] 签名密钥治理、SBOM、依赖扫描、隐私政策和漏洞响应。
- [ ] 配置迁移、备份/恢复、升级/降级与完整卸载。
- [ ] 用户可预览的脱敏诊断包和问题模板。

### M7 — “小黑小黑”与更多设备

- [ ] 自定义关键词模型的授权来源和可复现生成流程。
- [ ] 准确率、误唤醒、远场、噪声、功耗和回滚重新过门禁。
- [ ] 第二个独立设备/ROM profile 验证。
- [ ] DSP、CPU KWS、系统助手和手动入口保持同一产品行为。
- [ ] 根据实测发布“支持、实验性、不支持”设备矩阵。

## 4. 首版命令范围

### 低风险：首版直接执行

- 打开相册、浏览器、设置、应用宝或已安装 App。
- 打开指定网页、地图搜索、拨号盘但不直接拨出。
- 查询小黑、DSP、llama.cpp、Happy 和 OpenCode Web 的状态。
- 调整音量、打开手电筒等可逆操作；受系统限制时打开对应设置页。

### 中风险：预览后执行

- 汇总通知、复制识别文字、填写表单、修改可逆设置。
- 打开某个消息会话并填入草稿，但不自动发送。

### 高风险：每次明确确认

- 发送消息、拨出电话、删除内容、安装 APK、授予权限、修改安全设置。

### 默认禁止

- 付款、转账、批量消息、隐蔽监控、验证码读取后自动提交、绕过 App 风控或系统安全。

## 5. 产品工件清单

一个版本只有同时具备以下工件才算“可交付”：

- [ ] 通用 Android APK；OnePlus DSP 增强包独立打包。
- [ ] 可复现构建、正式签名、版本号、SHA-256 和 SBOM。
- [ ] 首次安装、升级、权限配置、常用命令和故障排除文档。
- [ ] 一键停用、完整卸载和设备专属回滚说明。
- [ ] 中英文 README、Release Notes、隐私说明和兼容矩阵。
- [ ] 真机验收记录，包含环境、步骤、期望、实际、证据和残留检查。
- [ ] 自动化测试和 CI 门禁；公开树秘密/私有资产扫描。
- [ ] 已知限制、风险边界、问题模板和诊断导出方式。
- [x] 手机内离线操作卡，断网时也能查到启停、模型切换和回滚步骤（[操作卡](phone-operation-card.zh-CN.md)）。

## 6. 时间与资源预估

以下是工程量级，不是未经实测的日期承诺：

| 阶段 | 单人聚焦开发的量级 | 结果 |
|---|---:|---|
| M1 | 1–3 周 | 当前 OnePlus 8T 的“小布小布→打开相册”真实闭环 |
| M2 | 再 2–4 周 | 10 个短命令、语音 UI、错误处理，可日常自用 |
| M3–M4 | 再 1–2 个月 | 通用 Android Alpha、通知汇总和确认式草稿 |
| M5–M6 | 再 2–4 个月 | 可见 Phone Agent、常用 App 回归、公开 Beta 稳定性 |
| M7/更接近厂商级 | 持续 6–12+ 人月 | 自定义低功耗唤醒、多设备、长期兼容和系统级体验 |

这台设备较快能实现厂商助手“看得见的主要交互”；最慢的部分不是接一个大模型，而是息屏唤醒、后台生命周期、功耗、权限安全、App 版本变化和失败恢复。OEM 可以直接修改系统镜像和预装服务，第三方公开产品必须通过兼容分层和用户授权弥补这部分差距。

## 7. 最近一个迭代的唯一主线

下一轮只追踪一条 P0 纵切：

```text
OnePlus 8T 息屏
  → “小布小布”DSP callback
  → 小黑短音频会话
  → 中文 ASR：“打开相册”
  → 固定 Intent 解析
  → 风险策略：低
  → 打开系统图片界面
  → 结果反馈
  → 麦克风释放并重新 ARMED
```

在这条链路通过三轮冷启动和三轮声学测试之前，不同时开发微信自动回复、视觉 Agent、自定义“小黑”模型或更多机型。这样既控制 Token、截图和模型调用，也能让每一次操作都沉淀成真实的产品验收案例。
