# 小黑威胁模型

## 保护对象

小黑保护麦克风音频、通知正文、联系人和消息目标、模型渠道凭据、UI 快照、用户意图、设备完整性、签名密钥及设备专属 DSP 资产。

## 信任边界与控制

- **唤醒 profile → 主 App：** 仅相同签名身份的 Companion 能通过签名权限；事件只有关键词 ID、置信度和 capture 标志，不含唤醒音频。
- **麦克风 → ASR/KWS：** 本地录音有时限、有可见提示，并在结果、错误、停止或生命周期中断时释放。通用 CPU KWS 需主动开启，且与 DSP 独立控制。
- **通知 → 助手：** 用户主动授权，只读取当前通知、不持久化，锁屏拒绝展示。消息草稿要求目标与全文的新鲜确认，产品不点击发送。
- **模型 → 执行器：** 模型只提议严格 JSON，没有 Accessibility 句柄。包允许列表、风险判定、精确语义匹配、步骤/时限/恢复上限、重复保护和全局停止均由本地强制。
- **UI → 导出轨迹：** 不写入快照、截图、Prompt、通知正文或 Token；敏感目标在有界 JSONL 落盘前替换。
- **构建 → 发布：** 私有 OEM 二进制和凭据不进入 Git。Release 必须用仓库外非 debug 密钥，并检查 APK 哈希、SBOM、权限、ZIP 路径、native 库及凭据特征。

## 设计上拒绝

支付、银行、凭据、密码和验证码页面默认拒绝。发送、删除、安装、卸载、授权、拨号和安全设置变更需要与目标绑定的新鲜确认，不能静默委托。私有 App 协议、安全绕过、隐藏 UI 自动化和后台代发消息不在范围内。

## 剩余风险

Accessibility 语义和 App 页面会变化；本地或远端 ASR 可能误识别；通知文本可能含对抗内容；root 设备 profile 扩大可信基；CPU KWS 更耗电；签名密钥泄漏会击穿 Companion 边界。因此公开发布仍必须具备真机页面、长待机、升级回滚、依赖、签名治理和模型许可证据。
