# 低置信度澄清

[English](intent-routing-clarification.md) · [三路意图分类](intent-routing-three-way.zh-CN.md) · [执行账本](execution-backlog.zh-CN.md) · [状态](../STATUS.md)

状态日期：2026-08-10。`ROUTE-003` 在原始文字和惰性三路分类器之间增加纯本地澄清策略。低置信短语只会变成追问，不会变成猜测的 Android 动作、模型调用或工具调用。

## 决策类型

| 类型 | 示例 | 结果 |
|---|---|---|
| `ASK_TARGET` | “打开相册和相机” | 要求用户精确选择一个目标。 |
| `ASK_INTENT` | “相册” | 询问用户想操作手机还是只讨论该主题。 |
| `ASK_SCOPE` | “帮我” | 追问缺失的处理目标与期望结果。 |
| `ROUTE` | “打开相册”或“相册是什么？” | 原样返回已有的确定性命令/聊天/复杂任务分类。 |

每个追问结果强制携带 `CHAT` 与 `CommandRouter.Action.UNKNOWN`，提示明确说明没有猜测、没有执行。每个结果固定记录 `modelCalls=0`、`actionCalls=0`。

## 有意收窄的规则

- 同时命中多个已审核动作目标时，追问具体目标。
- 一小组精确的不完整短语触发任务范围追问。
- 裸动作主题，以及旧关键词路由会当成动作但又没有概念问句线索的短语，触发动作意图追问。
- “是什么、为什么、怎么、如何”等概念线索继续按聊天问题处理。
- 明确的确定性命令和明确的复杂请求不在这里被拦截。高风险请求被分类不等于获得授权，后续策略仍必须拒绝。

这是保守的命令边界，不是通用自然语言理解。它有意不使用模糊匹配，也不会把不清楚的文本发给模型来决定动作是否安全。

## 验收与接入边界

合成、非私人矩阵包含 50 条文本：10 条目标歧义、10 条动作意图歧义、10 条范围缺失和 20 条明确对照。30 条歧义全部追问、携带未知命令且零副作用；20 条明确输入保持可路由。静态门禁拒绝 Android API、动作分发、模型客户端、工具网关、shell 和网络。

`RouteClarificationPolicy` 目前有意不被 `MainActivity` 引用。`ROUTE-004` 已提供版本化、未确认的 `ActionRequest`；后续接入仍必须等待有边界规划、策略与新鲜确认，才能在不把模型文字变成权限的前提下连接可见动作流程。
