# 产品说明

[English](product-brief.md)

## 产品定位

小黑是 Android 用户与本地/远端 AI 工具之间可信的“行动层”。它不是另一个聊天窗口：按需被唤醒，只处理一个有边界的命令，解释准备执行的动作，在必要时取得确认，再通过可观察的 Android 机制操作手机。

## 目标用户

- 希望助手可检查、可控制的 Android 深度用户。
- 构建设备本地语音与 Agent 体验的开发者。
- 在真实硬件上验证低功耗唤醒、端侧 AI 和用户式 UI 自动化的研究者。

## 分发策略

公开产品先做通用 Android 核心，而不是把 OnePlus DSP 集成设为下载前提。每个可下载版本至少提供手动按钮、快捷设置、快捷方式或设备支持的系统助手入口；设备专属低功耗唤醒通过能力探测后作为独立后端安装。

这把两类结论分开：

- 小黑的命令、策略和 Android 动作体验可以广泛迁移。
- 常驻低功耗 DSP 唤醒属于硬件、固件和系统集成，必须有明确设备 profile。

## 第一条产品纵切

点击或唤起小黑，然后说：“打开相册。”

范围刻意收窄，但必须先在普通 Android 完整打通短命令录制、ASR、结构化意图、低风险策略决策、Android 动作和可见结果。息屏 DSP 唤醒是支持设备上的附加验收路径，不是通用 Alpha 的前置条件。

## 小黑自身负责

- Wakeword Broker 生命周期和用户可见状态。
- 短语音命令会话与 ASR 适配器契约。
- 意图、策略、确认和审计决策。
- Android 动作注册表与结果展示。
- 产品 UI、引导、权限、状态与本地历史。

## 明确不做

- 重写 OpenCode、Claude、Happy、llama.cpp 或模型 Provider 配置。
- 分发私有唤醒模型、OEM 应用、platform 密钥或大模型权重。
- 冒充 App 私有协议或绕过系统/App 安全控制。
- 未经明确确认就发送消息、删除数据、支付或修改安全设置。
- 用一台 OnePlus 8T 的结果宣称广泛设备兼容。

## 首个公开 Alpha 的成功标准

1. 全新安装说明至少在一台未 root 的通用 Android 和 OnePlus 研究 profile 上可复现。
2. 没有 DSP 后端时，基础唤起仍可使用。
3. 每个唤醒后端在启用前返回 `available`、`unsupported`、`permission_required` 或 `ready`。
4. “打开相册”成功并生成结构化、脱敏的验收报告。
5. OnePlus DSP 后端单独通过物理拔线功耗与息屏回归。
6. stop、卸载、重启、权限拒绝和依赖失败都具有实测恢复路径。
