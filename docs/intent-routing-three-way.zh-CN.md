# 三路意图分类

[English](intent-routing-three-way.md) · [执行账本](execution-backlog.zh-CN.md) · [状态](../STATUS.md)

状态日期：2026-08-10。`ROUTE-002` 新增纯粹、无副作用的三路分类器：普通聊天、已有确定性短命令、未来需要规划的复杂任务。分类不会启动模型或 Android 动作。

## 规则优先顺序

1. 已由 `CommandRouter` 识别的精确通知查询/消息草稿句式可以保留为确定性命令；但“回复消息是什么意思”这类概念问题不能只因旧路由命中关键词就被信任。
2. “然后、完成后、并且、接着”及英文等明确多步骤标记归复杂任务；本层不会规划或执行。
3. 其他确定性命令必须同时满足已审核 `CommandRouter` 结果和“打开、关闭、导航、显示”等明确祈使线索。
4. “打开相册和相机”这类多目标歧义保持惰性，暂时返回聊天/非动作路由；`ROUTE-003` 会把低置信变成显式追问，而不是猜。
5. 明确整理、查找、比较、同步、报告、批量等线索归复杂任务。高风险请求也可能进入复杂类，但后续策略必须拒绝；分类不等于授权。
6. 其余默认聊天。

每个结果固定 `modelCalls=0`、`actionCalls=0`。非命令结果的 `CommandRouter.Action` 固定为 `UNKNOWN`，下游不能误用关键词产生的 Android 动作。

## 验收

合成、非私人矩阵精确包含 100 条：40 条确定性命令、35 条聊天、25 条复杂任务。覆盖包含命令词的概念问题、一个双目标歧义命令、多步骤请求、中英文变体和高风险转账请求；全部分类符合预期，结果全部零副作用。

静态门禁拒绝分类器引用 Android API、动作分发、模型客户端、工具网关、shell 或网络，并确认 `MainActivity` 尚未使用它。真实用户路径接入等待 `ROUTE-003` 的低置信追问和 `ROUTE-004` 的未确认 `ActionRequest`，避免本基础任务静默改变现有命令行为。
